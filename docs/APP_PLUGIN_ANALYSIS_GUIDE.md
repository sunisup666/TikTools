# 从应用故障分析到插件实现：给工程 Agent 的实作指南

本文提炼 TikTools 开发中的可复用方法，帮助后续 Agent 分析其他 Android 应用，并实现界面辅助、定位测试、翻译或应用互操作插件。重点是如何取得证据、缩小改动、验证真实行为和交付可回退的结果。它不是适用于所有应用的 Hook 清单，也不提供绕过付费、账号授权、设备证明或安全检测的方案。

本文记录公开的工程步骤与决策依据，不包含用户原始备份、账号内容、实际位置、设备序列号、密钥或内部逐字推理记录。示例包名 `com.example.target` 和其他示例值均为占位符。

## 1. 先读这次案例的边界

本项目的实机基线是 **Redmi K40、Android 17、Vector 2.2、TikTok `com.ss.android.ugc.trill` 47.4.3 / 470403**。当前项目使用传统 Xposed API 82 接口；这不代表所有宣称兼容 Xposed 的框架都有相同的配置访问、加载时机与运行行为。

起点是旧插件启用时 TikTok 出现闪退或黑屏，停用后恢复播放。旧插件启用时曾观察到原生 `SIGSEGV`、ART 栈与特定后台线程；这只能证明故障发生的位置及其与插件启用的关联，不能直接证明内核、某个 Java 返回类型或某一行第三方代码是根因。部分功能关闭后仍黑屏，也说明“没有再次崩溃”不等于恢复业务。

随后按可观察接口独立实现新模块，分别验证接口值、设置页面与 TikTok 实际场景。内部版本已有地区/定位/设备接口、部分界面规则、评论过滤、实际翻译、视频保存以及地图预设的实机验证记录，见 [TESTING.md](TESTING.md)。**公开版包名迁移、每次新构建和后续应用版本仍需重新核验，不能继承成未经复测的通过结论。**

未覆盖的另一个 TikTok 包名、其他版本、其他 ROM 或框架应视为待验证。短时间播放正常和用户日常使用反馈都很有价值，但不能证明长期稳定或服务端一定采用模拟字段。

## 2. 把用户症状改写成可判定的问题

先用一句话写明：**什么操作，在什么页面，启用什么后，出现什么，与停用时有什么差异。** 不要直接把“黑屏”翻译成“需要换内核”。

开始前记录以下信息，公开文档中只保留必要的非敏感项：

| 类别 | 最少需要记录 | 用途 |
| --- | --- | --- |
| 目标应用 | 包名、versionName、versionCode、主/子进程 | 排除同名应用、渠道差异和错误进程 |
| 安装组成 | 单 APK 或 split APK、ABI | 避免只分析 base APK 而漏掉本机库或配置资源 |
| 系统 | Android/API、ROM、设备架构 | 判断接口存在性和平台差异 |
| 插件框架 | 名称、版本、模块启用状态、作用域 | 区分安装、加载和实际拦截 |
| 功能 | 总开关、分组开关、相关配置 | 确认复现变量 |
| 外部条件 | 网络/VPN是否可用、必要权限、登录状态 | 排除连接或权限故障；不记录凭据 |
| 用户资产 | 是否有草稿、模型、收藏、配置 | 决定备份和回退方式 |

以可观察结果定义验收，例如：“冷启动后可以播放，连续切换两个普通视频，进程未重启；开启文案隐藏后只隐藏文案，视频继续播放。” “已安装”“Hook 数量大于零”都不构成这个验收结果。

只读取需要的应用目录。不要清空目标应用数据来获得一个干净页面；这可能删除账号状态、草稿和离线内容。没有必要时也不要更新 ROM、内核或整个框架。

## 3. 先做停用对照，再做最小改动

建议按以下顺序实验，每次写下输入、结果与仍未解释的现象：

1. 保存当前可用配置、框架作用域及必要的插件数据；确认用户可以继续使用。
2. **只停用可疑插件**，强行停止并重新启动目标应用，复现同一个业务操作。
3. 若停用后仍失败，先查网络、权限和应用自身日志，不把问题全部归给插件。
4. 若停用后恢复，保持系统与应用版本不变。优先按功能组二分，再缩到具体入口；每轮只改变一个变量。
5. 新实现先保留原行为，逐组开启。每次既检查目标功能，也检查播放、导航、返回等关键业务。
6. 如果一次改动同时影响多个字段，明确把它作为一个有依据的预设整体；不要把它解释为已定位某一个字段的作用。

停用对照需要**新进程**：仅切回桌面，旧 Hook 或静态字段修改可能仍留在内存中。多个修改同一接口的插件不要同时启用来做归因。根因未确定时写“当前证据支持插件相关”，不要写“已经证明是内核问题”。

## 4. 建立可复核的证据链

### 4.1 每次运行都有身份

为测试生成 `run_id`，记录开始时间、构建摘要、目标包名/版本、PID、配置摘要、操作步骤与结束结果。时间和 PID 一起使用：同 PID 只能排除该次观察期间的进程重启，不能排除 ANR、网络失败或播放器卡死。

建议本地测试目录如下；原始材料默认不发布：

```text
test-artifacts/<run_id>/
  manifest.json          # 版本、构建摘要、测试场景与时间
  result.json            # 实际断言和结论
  screenshot.png         # 可能含私人内容，仅本地留存
  active-window.xml      # 同上
  current-process.log    # 过滤后保存，不收集整个账号流量
  config-before.bin      # 私有备份，禁止打包发布
```

新的结果不能从“目录里最新的旧文件”推断。启动测试前删除自己上一轮的结果文件，或让结果带回 `run_id`；读取后校验运行标识、包名、版本与时间。导出报告经过系统文件选择器时，还要确认已真正保存，而不是再次拉取旧报告。

### 4.2 日志、截图、视图树各自回答不同问题

| 证据 | 可以支持什么 | 单独不能支持什么 |
| --- | --- | --- |
| 当前 PID 与崩溃日志 | 当前进程是否重启、异常线程及栈 | 页面能否播放、异常一定由哪段插件代码导致 |
| 屏幕截图/短时连续观察 | 可见元素、黑屏、交互反馈 | 隐藏元素的内部状态、媒体地址对应关系 |
| 即时视图树 | 活动窗口、元素文本/ID/边界、点击目标 | 所有自绘内容、不可访问的播放器内部状态 |
| Hook 诊断 | 是否安装拦截、接口值、规则命中 | 服务端采用了字段、业务已经成功 |
| 实际业务产物 | 翻译文本、完成下载的可播放文件 | 其他版本或所有内容类型也能工作 |

过滤日志前先确定 PID。例如下列命令只用于已授权的测试设备：

```powershell
$targetPackage = 'com.example.target'
adb shell dumpsys package $targetPackage
adb shell pm path $targetPackage
adb shell pidof $targetPackage
# 把该轮真实 PID 填入；PID 变化后须重新采集。
adb shell logcat -b crash -d --pid=12345 -t 300
```

不要只搜索 `Exception` 就宣布失败，也不要只搜索不到 `FATAL` 就宣布成功。关联时间、进程、调用路径和用户症状。播放验证优先使用实际播放器状态或连续画面与操作观察，并结合用户确认，不能把一张有封面的截图当成视频已播放。

### 4.3 动态页面不要无限等待“空闲”

连续播放、动画和信息流可能让依赖 idle 的自动化采集超时。也可能上次 XML 仍在本地，误以为本轮采集成功。

本项目使用一次性 instrumentation，通过 `UiAutomation.getRootInActiveWindow()` 读取当前窗口，限定重试、节点数和树深度，再将 XML 以 Base64 返回。参考 [InspectInstrumentation.java](../probe/src/main/java/io/github/sunisup666/tiktools/probe/InspectInstrumentation.java) 与 [device_ui.py](../tools/device_ui.py)。它不需要等待整个播放页面停止动画；仍须检查根节点存在、目标包名、可见性与采集时间。

每次点击前取新快照，确认窗口包名、节点可用状态和非空边界；点击后再读新状态。用户正在切应用时要停止依赖页面位置的自动点击。固定坐标只能用于已校验尺寸、方向与前台窗口的短期测试，不能作为通用适配方案。

## 5. 从观察到独立实现，控制 Hook 边界

### 5.1 先选最窄的入口

优先考虑系统公开 API、应用公开接口、Intent 或受控 ContentProvider；只有这些不能满足需求时再选择应用内部接口。观察已有插件的功能描述、用户交互和公开接口行为，可以形成自己的功能规格；不要把第三方二进制反编译结果或资源直接复制进新项目。依赖与素材另行记录来源、许可和使用范围。

可以只读查看自己有权分析的 APK 结构、方法签名、资源和调用行为。静态分析找到名字后，仍需用运行时证据确认它在当前版本被调用。类名看起来像播放器，并不意味着某个方法收到的就是当前可见视频。

每个 Hook 规格至少写明：目标包/进程、类加载器、类名、方法名、参数类型、返回类型、安装时机、配置开关、失败时保留的原行为。对重载逐个核对，不要仅按方法名批量替换。

### 5.2 Java 返回类型必须完全匹配

`double`、`float`、`int`、`long` 和对应的包装类型不能随意互换。定位精度一般是 `float`，经纬度是 `double`；同类基站标识也可能分别返回 `int` 或 `long`。下列是示意片段，不是一个通用定位插件：

```java
Method method = Location.class.getDeclaredMethod("getAccuracy");
if (method.getReturnType() != float.class) {
    throw new IllegalStateException("Unexpected signature");
}
XposedBridge.hookMethod(method, new XC_MethodHook() {
    @Override protected void beforeHookedMethod(MethodHookParam param) {
        if (!enabled || !Float.isFinite(configuredAccuracy)
                || configuredAccuracy <= 0) return;
        param.setResult(Float.valueOf(configuredAccuracy));
    }
});
```

把不同数字类型放在三元表达式或通用 `Number` 计算里，可能发生数字提升或装箱变化。应显式分支、显式包装，再验证实际接口返回值。不要为了让 Hook 不报错而返回 `null`、固定零或压掉目标应用所有异常。

缺类、缺方法或签名变化时，关闭该适配并写入有限的诊断项。只有在能够安全返回的边界内处理异常，**不确定时保留原行为**。不要通过修改 SELinux、扩大目录权限或影响所有进程来修复一个应用内功能。

### 5.3 系统字段变化不是硬件变化

修改目标进程的 Build、Locale、时区或定位 getter，只影响它观察到的一部分值。它不会改变真实硬件、实际网络出口、GNSS 事件来源、服务端数据或设备证明。

系统版本模拟尤其要保守：应用可能依 `SDK_INT` 选择本机不存在的 API，部分调用点还可能缓存或内联旧值。默认保留真实版本，必须单独开启、单独复测。定位 getter 替换也不会凭空产生系统没有发送的定位事件；权限、提供方可用性、时间戳和 mock 标记应保持原有语义。

参考 [HookEntry.java](../app/src/main/java/io/github/sunisup666/tiktools/HookEntry.java) 中按组开关、返回类型检查与兼容性诊断的实现；移植到其他应用时重新审查参数和调用时机。

## 6. 页面适配：语义、版本与播放器安全

### 6.1 不把资源名当成跨版本协议

常见资源名可作为候选，但混淆 ID 必须与实际包名、versionCode、页面上下文一起限定。本项目针对 `com.ss.android.ugc.trill` / `470403` 的特定资源规则只在该版本启用，不能复制给另一个包名或新版本。

一个可靠的页面规则通常结合：

- 资源 ID 或明确的可访问性语义。
- 当前业务页面及祖先结构，例如普通信息流而非评论弹层。
- 可见区域交集、尺寸和大致位置。
- 对应功能开关及播放器排除规则。

`isShown()` 不足以排除 ViewPager 预加载的屏外页面。读取文案和匹配规则前，还要检查屏幕坐标与 `getGlobalVisibleRect()`。自绘控件可能不是 `TextView`，但能从已验证版本的布局对象或 accessibility 节点取得文本；读取方式也要受版本和页面范围约束。

### 6.2 隐藏小视图，不碰未知播放器容器

首次匹配时保存原可见性，优先对已识别的小视图使用 `INVISIBLE`，减少布局重排。离开匹配状态、视图复用或功能停用时恢复原值；不能一律恢复成 `VISIBLE`，否则可能显示原本就应隐藏的控件。

排除包含 `SurfaceView`、`TextureView`、`VideoView` 的祖先容器；对无法判定的深层树保守跳过。限定扫描预算、深度和周期，在 Activity 暂停/销毁后停止任务。界面改动放在主线程，模型下载和网络工作放在后台。

即使某个大容器的文字像“推荐”，也不要直接删除它。隐藏后必须复测视频、手势切换、评论入口和返回。黑屏出现时首先回退该规则，而不是继续隐藏更多父节点。

### 6.3 区分瞬时匹配、累计匹配和业务效果

本项目诊断中：

- `ui_matches` 表示最近一次扫描命中的视图数量。
- `ui_total_matches` 在视图首次进入当前隐藏集合时累计；恢复后再命中可能再次计数，**不是独立视频、评论或用户的数量**。
- `installed_hooks` 表示安装了多少方法拦截，也不是调用次数或业务成功次数。

评论弹层关闭后瞬时匹配为零，不能据此否定此前确实过滤过评论；累计值大于零，也不能证明当前页面隐藏正确。结合当时截图、页面 XML、操作时间与前后效果判断。参考 [UiAdapter.java](../app/src/main/java/io/github/sunisup666/tiktools/UiAdapter.java)。

## 7. 媒体、文案与异步结果必须对应当前内容

信息流会预加载下一条、缓存上一条。**最后看到的 URL 不等于当前播放 URL**。翻译后的文案也可能和原始数据模型的描述不同。

优先用稳定内容 ID 关联当前可见条目和媒体对象。若当前版本只能可靠识别文案，可建立有大小上限的候选表，将原文、内容描述和已确认的译文映射到内容 ID，再与可见文案对应；保留 ID，用于发现同文案不同内容的歧义。本项目采用了这种降级方案，见 [MediaCatalog.java](../app/src/main/java/io/github/sunisup666/tiktools/MediaCatalog.java)。

以下情况应清空当前候选或拒绝执行：

- 当前页没有可识别文案、文案与候选不符，或同一文案对应多个内容 ID。
- 页面已切换，但异步翻译/媒体查询仍返回旧条目结果。
- URL 对应分段流、受保护内容，或保存需要未支持的鉴权信息。

翻译请求携带当前文案/条目标识，完成后再次核对页面身份；不把上一条翻译留在下一条上。空文案连续出现时清除旧状态，不能一直沿用最后一次成功匹配。

实际保存需要用户确认；验证下载管理器终态和输出文件的音视频轨，再确认内容与屏幕对应。`enqueue()` 返回任务 ID 只代表入队。不要打印完整媒体 URL、鉴权参数或 Cookies；对无法明确对应当前内容的候选，显示不可用比保存错视频更合适。

## 8. 配置、预设与跨进程访问

### 8.1 让配置减少错误，而不是制造不一致

按用户任务提供成组预设：国家、运营商、MCC/MNC、Locale、时区与默认城市保持合理对应，保留手动高级入口。设备字段优先读取本机真实值，不凭空拼一套硬件和版本组合。预设只是模拟参数，不代表真实网络或设备认证。

记录定位来源：地区默认点、城市预设、地图手选或手填。用户确认地图位置后，后台 IP 更新不应覆盖该坐标；先保存草稿，点击“使用此位置”才提交，取消保持原配置。地图需明确坐标系，本项目用 WGS84；地图显示投影与保存的经纬度要区分。

验证经纬范围、日期、MCC/MNC 长度、BSSID 格式、有限数值、路线长度/速度等约束。检查时区是否确实存在，避免无效 ID 静默落到默认值。导入 JSON 有 schema、大小限制和错误提示；不要只验证语法合法。

### 8.2 Provider 是权限边界

导出 Provider 不代表允许所有应用调用。身份来自 Binder 调用 UID 及其对应包，而不是请求 Bundle 里自报的包名；诊断应用还应要求与模块同签名。共享 UID 场景需要单独审查，不能把一个 UID 返回的包列表误解为唯一调用身份。需要更严格的官方目标信任时，可另加已审核的签名策略，不能声称包名白名单本身就是证书验证。

涉及模块自己的模型、文件或系统服务时，先验证调用者，再以模块身份执行。示意：

```java
int callingUid = Binder.getCallingUid();
Caller caller = requireAllowedCaller(callingUid); // 检查 UID 映射及必要签名
validateOperation(method, extras, caller);        // 功能开关、大小、参数边界
long token = Binder.clearCallingIdentity();
try {
    return performAllowedOperation(method, extras);
} finally {
    Binder.restoreCallingIdentity(token);
}
```

`clearCallingIdentity()` 解决的是 Binder 调用身份传播，不是授权。不能先清除身份再检查原调用者，也不能把它当成绕过拒绝访问的万能修复。异步任务要显式传入已验证且最少的参数，不能在另一线程假定原 Binder 调用仍存在。

限制诊断长度、翻译文本长度、操作种类和 URL 方案，不提供任意文件路径、任意命令或任意配置写入口。仅允许 HTTPS 也不等于所有下载都获得用户授权。普通诊断不记录用户名、完整文案、位置或令牌。项目参考：[SettingsProvider.java](../app/src/main/java/io/github/sunisup666/tiktools/SettingsProvider.java)。

### 8.3 探针与生产配置分离

探针专门验证实际 framework getter，使用自己构造的 `Location`、测试 SSID 和模拟字段。测试配置只向同签名探针返回，生产目标继续读取用户配置；IP 自动更新等副作用也不能被探针触发。生产和探针诊断分别存储，避免测试报告覆盖实际加载状态。

不要把“测试 UI 有 12 个示例视图，全部隐藏成功”写成“TikTok 的 12 类页面元素全部适配”。前者验证规则引擎，后者需要真实页面证据。参考 [device_test.py](../tools/device_test.py)。

## 9. 测试分层，避免用实现证明实现

| 层级 | 有效验证例子 | 不能替代的上层验证 |
| --- | --- | --- |
| 纯计算 | 地图投影往返、路线距离、预设一致性 | 真实手机上的地图手势和坐标保存 |
| 探针进程 | 调用真正的系统 getter，比较启用/停用值 | 目标应用是否读取该接口 |
| 设置页面 | 打开各页、选预设、保存/取消、重启读取 | 注入进程是否加载同一配置 |
| 目标应用 | 实际隐藏、翻译、评论过滤、切页播放 | 未遇到的页面和所有账号场景 |
| 交付安装 | 发布 APK 安装后加载、迁移和回退 | 长期稳定及未来版本兼容 |

不要先调用一个“返回预设配置”的函数，再断言它等于同一份预设，就声称接口模拟成功。getter 测试应经过实际框架和 Hook；下载测试要检查真实终态；翻译要得到真实模型输出；地图要验证点选方向、缩放和平移后的选点保留、保存与取消。

建议最少覆盖总开关关闭、单组开启、代表性的组合、冷启动和一项关键业务回归。涉及异步功能再补切页后旧结果不显示。跟变更有关的检查通过后，不为了制造“测试很多”而重复折腾用户手机。

### 配置恢复必须覆盖失败路径

优先使用隔离探针。必须临时改变真实配置时，先停止会缓存/写回该配置的进程，逐字节保存；最后验证恢复摘要。示意：

```python
original = read_private_config()     # bytes；只保存在私有测试目录
try:
    stop_target_and_settings_app()
    write_test_config()
    launch_and_verify_current_run()
finally:
    stop_target_and_settings_app()
    restore_private_config(original)
    assert read_private_config() == original
    restore_temporary_scope_and_device_settings()
    relaunch_normal_app()
```

实际脚本还要记录恢复失败，不能把它吞掉然后输出通过。保留一份本地恢复说明，以处理断电、进程被杀等无法运行 `finally` 的情况。设置开关、作用域、屏幕常亮、临时文件和测试下载都要纳入收尾；不要删除非测试产生的用户文件。项目集成示例：[tiktok_test.py](../tools/tiktok_test.py)。

## 10. Windows、PowerShell 与 ADB 的实际坑

### 中文显示错误与源文件损坏要分开诊断

PowerShell 控制台显示乱码，不一定是文件已损坏；反过来，带中文的 here-string 经非 UTF-8 管道传给 Python，可能在进入脚本前就已经变成问号。`PYTHONIOENCODING=utf-8` 只控制 Python 标准流，不能修复上游已经损坏的字符。

使用明确的 UTF-8 文件读写和编辑补丁。路径尽量从 `Path.cwd()` 或脚本位置推导。必须走管道时，先配置两端编码，再用无敏感内容的短文本验证；对关键文件读回检查，不能只凭终端看起来正常判断。可用 `python -X utf8` 执行已保存的 UTF-8 脚本。

### 二进制 ADB 输出不经过文本管道

截图、APK 或压缩备份应由程序直接接收字节；不要经过旧版 PowerShell 的文本重定向或字符串解码再编码：

```python
from pathlib import Path
import subprocess

adb = ["adb"]  # 多设备时在本地通过 -s 选择；不写入公开文档
png = subprocess.check_output(adb + ["exec-out", "screencap", "-p"], timeout=20)
assert png.startswith(b"\x89PNG\r\n\x1a\n")
Path("test-artifacts/current.png").write_bytes(png)
```

### 本地参数数组不代表远端没有 shell

优先 `subprocess.run([...])`，避免拼 Windows 命令字符串。但 `adb shell` 与 `su -c` 后仍可能被远端 shell 解析，包含空格、引号、`$()` 或反引号的参数尤其要小心。JSON 编码不是 shell 转义。

远端路径和包名必须来自已验证值。多行、固定且可审阅的 Root 测试脚本可经 stdin 传给 `adb shell su -c sh`，加 `set -e`、明确超时和 `exit 0`，不要把用户输入直接插入脚本。只有包名/路径命令时也要使用适合远端 POSIX shell 的引用；不能把 PowerShell 转义规则套在 Android shell 上。

自动解析文件名时，不依赖 `ls` 的默认排版；它可能把多个文件放在同一行。对已限定名称的目录使用 `ls -1`，或使用明确的结构化/分隔协议，再验证每个名字。后续创建目录、复制和修改属主的条件应来自实际通过校验的文件清单，不能只凭一个宽松的前缀判断。

PowerShell 执行策略阻止 `.ps1` 时，可用现有 Python 构建入口，不要为一次构建修改全局策略。Gradle 锁住产物时，仅停止本项目 daemon，再重新构建；避免同时编辑编译输入和进行发布构建。

## 11. 包名、签名、UID 与数据迁移是一项独立变更

应用显示名变化和 applicationId 变化不一样。改包名还会影响 Provider authority、显式组件、框架作用域、查询可见性、私有路径、模型与数据归属。优先在公开发布前固定包名；后续普通更新保持包名和签名连续。

同包名换签名不能当作普通覆盖安装；新包名通常有新的 UID。迁移不要只把旧目录整包复制过去：

1. 先安装并启动新应用，让系统建立它自己的 CE/DE 目录；CE 数据需要用户解锁后处理。
2. 备份必要配置和旧安装包，校验 JSON schema。模型等可再下载资产单独评估。
3. 只迁移明确需要的文件，不复制账号 token、缓存身份或整个系统目录；检查意外符号链接。
4. 从新目录读取真实 UID、属主和 SELinux 上下文，恢复到新文件；不能硬编码旧 UID 或只改 mode 位。
5. 检查包含 MCS 类别的完整标签。错误标签可能导致权限拒绝，即使 Root 能看到文件也不代表新应用能读。
6. 停用旧模块，启用新模块作用域，冷启动目标；确认报告中的新包名、版本和用户配置一致。
7. 核验已下载模型可用；失败时保留重新下载路径。确认回退可用后再清理自己创建的暂存文件。

不要 `chmod 777`、关闭 SELinux 或卸载目标应用来掩盖迁移错误。Root 复制只是维护者在已授权设备上的迁移工具，不应成为普通产品使用流程。项目示例：[migrate_legacy.py](../tools/migrate_legacy.py)。

## 12. 构建、安装、发布与收录分别验收

建立从源码到用户安装文件的链条：

1. 固定版本号、构建工具和依赖，记录源码提交及必要构建输入摘要。
2. 构建开始/结束核对输入未变，要求构建退出码成功；旧 APK 仍在磁盘不代表本轮成功。
3. 读取 APK 的 applicationId、versionCode/versionName、签名证书摘要与 SHA-256。
4. 安装该 APK，再拉取当前安装路径的文件计算摘要；split APK 需要按组成逐个对应。
5. 验证框架加载的是新版本；安装成功不等于作用域生效。
6. 发布源码提交、标签和 Release 资产，再把下载回来的 APK 与本地产物比较。

可用以下命令检查自己构建的 APK；根据 SDK 安装位置调用工具，不把私钥密码写入命令历史：

```powershell
apksigner verify --verbose --print-certs .\release.apk
apkanalyzer manifest application-id .\release.apk
apkanalyzer manifest version-code .\release.apk
Get-FileHash -Algorithm SHA256 .\release.apk
```

摘要一致证明文件一致，不证明安全、兼容或所有功能正确。源码输入摘要也不等于可复现构建，除非已控制并复测工具链、依赖及其他构建输入。项目构建入口：[build.py](../tools/build.py)。

发布前检查 Git 跟踪清单与源码归档内容，排除签名 keystore、凭据、`local.properties`、原始截图、手机备份、用户配置、诊断探针结果和带参数的 URL。`.gitignore` 不会自动移除已跟踪文件；发现历史中泄露凭据时需要单独处理，不能仅在当前提交删除。

仓库已推送、GitHub Release 已可下载、模块目录已接受、Vector/LSPosed 中能看到下载条目，是不同的完成状态。目录申请规则以提交时的官方要求为准，参考本项目 [RELEASING.md](RELEASING.md)。提交申请或收到机器人回复后，不能提前宣布“已收录”。公开反馈只附脱敏复现资料。

## 13. 将工作流用于其他插件类型

| 插件类型 | 优先观察入口 | 核心验收 | 常见误判与调整 |
| --- | --- | --- | --- |
| 界面辅助/阅读优化 | Activity、可访问性语义、布局资源 | 指定元素改变，导航/滚动/播放器仍工作 | 不能把整个父容器隐藏；WebView、Compose 或自绘界面需另选观察方式 |
| 地区/定位测试 | 公开系统 getter、权限和定位事件 | 探针值正确，目标确实读取，关闭后恢复 | getter 成功不保证服务端地区变化；不伪造硬件证明 |
| 翻译/字幕辅助 | 当前可见文本、内容身份、模型状态 | 实际模型输出，切页不串文案，失败能恢复 | 不抓取任意屏幕私人文本；处理缓存、原文/译文和异步生命周期 |
| 应用互操作 | Intent、公开 Provider、分享协议 | 可信调用方、参数正确、取消与返回正常 | 优先公开协议；防止变成任意文件读取或权限代理 |
| 媒体保存辅助 | 当前条目 ID、已授权媒体模型 | 保存正确内容，任务完成，文件可播放 | 预加载、重复文案、分段流、鉴权均需单独判断 |
| 开发调试/兼容适配 | 明确版本的公开接口或最小内部入口 | 原业务恢复，移除适配后能回到基线 | 不因局部异常修改全系统；对缺签名/缺类显式降级 |

迁移时保留“基线—最小改动—多种证据—真实业务—恢复—交付”的顺序，重新选择目标接口。不同 UI 技术、进程模型和权限边界需要不同适配，不能搬运 TikTok 的混淆 ID 或媒体模型类名。
